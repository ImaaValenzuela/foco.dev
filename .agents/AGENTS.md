# Instrucciones de trabajo

Al completar una tarea, responde con el contenido completo para pegar en el template de PR del repositorio afectado: título Conventional Commit, resumen, tipo, archivos, pruebas, riesgos, variables de entorno, dependencias entre repositorios y checklist.

Las aplicaciones viven en repositorios hijos. Crear ramas desde `develop`, abrir PRs normales hacia `develop` y usar `main` solo para releases y despliegues.

Evita agregar comentarios en el código salvo que expliquen una decisión técnica no evidente. Antes de entregar cualquier tarea, ejecuta el lint del repositorio y las verificaciones disponibles, incluyendo build y tests cuando existan; corrige los errores y reporta explícitamente cualquier verificación no ejecutada.
